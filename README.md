# StreamWeaver Marketplace

The community catalog for StreamWeaver plugins, blueprint templates, overlays, themes, and speech voices.

This repository holds **manifests** — small JSON files describing each published package. The actual artifact bytes live on the author's chosen hosting (typically a GitHub Release on their own repo, or raw github content). Every manifest pins the SHA-256 of the artifact, so client apps refuse downloads whose bytes have been tampered with since publication.

The repository also publishes a static browse site at `https://agash.github.io/streamweaver-marketplace/` that consumes the same registry shards as the in-app browser.

## Structure

```
packages/
  plugins/<scope--name>/<version>/package.json
  overlay-components/<scope--name>/<version>/package.json
  overlay-components-static/<scope--name>/<version>/package.json
  overlay-themes/<scope--name>/<version>/package.json
  overlay-presets/<scope--name>/<version>/package.json
  templates/<scope--name>/<version>/{package.json, template.swtemplate.json}
  template-packs/<scope--name>/<version>/{package.json, pack.swtemplate-pack.json}
  speech-voices/<scope--name>/<version>/package.json

registry/                            # generated by CI on merge to main
  index.json
  plugin.json
  template.json
  template-pack.json
  overlay-component.json
  overlay-component-static.json
  overlay-theme.json
  overlay-preset.json
  speech-voice.json
  schema/
    package.schema.json
    registry.schema.json

site/                                # static browser site (GitHub Pages)
.github/workflows/                   # validate-pr, publish-registry, publish-site, reverse-verify
```

## Publishing a package

See [CONTRIBUTING.md](CONTRIBUTING.md) for the full author guide. The short version:

1. Build your artifact (`.swplugin`, `.swpkg`, `.swpkg-static`, `.swtemplate.json`, etc.).
2. Publish it somewhere reachable (GitHub Release, raw github content, your CDN).
3. Open a PR adding `packages/<type>/<scope--name>/<version>/package.json` with the artifact URL.
4. CI verifies the manifest + downloads the artifact + computes its SHA-256.
5. Maintainer reviews and merges.
6. The published-registry workflow regenerates the shards. The Pages site redeploys automatically.

First-party packages live under `@streamweaver/*`. Community packages use `@<your-handle>/<name>`.

## Trust model

This catalog uses **manifest-only PR review with SHA-256 pinning**. We verify the publishing author's bytes at PR-merge time and commit the hash. Clients refuse downloads that don't match. We do not mirror the bytes ourselves.

This defeats post-merge swap attacks but does not catch malicious-from-day-one packages. The runtime permission gate in the StreamWeaver host is the only enforcement that observes actual plugin behavior. **Treat community packages the same way you treat any other third-party software you install.**
